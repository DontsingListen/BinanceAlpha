# 背景与范围

## 项目背景

原项目位于 `<prior-research-project>`，围绕 Solana meme 的发现、结构观察和证据积累开展研究。它已经形成一些值得保留的设计经验：区分行情发生时间与实际获知时间，保留失败和排除记录，用同一套纯逻辑支持实时评估与回放，明确显示缺失或过期的数据。

本轮需求从 Solana meme 扩展到二段、交易异动、Binance Alpha 和“妖币”，不限链、不限中英文开源资料。用户计划另建独立项目，希望第三方能够凭本地材料继续实施并审核，不依赖聊天上下文。

这里的“二段”是本项目的工作定义：在可观察窗口内出现一次明显上涨，随后发生有边界的回撤和成交收缩，再出现突破迹象。它不是一种已有统一标准的交易信号。“妖币”也只表示高波动研究对象，不是资产质量或未来收益判断。

## 已确认要求与设计建议

| 类型 | 内容 |
| --- | --- |
| 用户已确认 | 新建独立项目；交接材料放在 `.` |
| 用户已确认 | 承接此前二段、Alpha、异动扫描仓库研究，提供具体执行方案 |
| 用户已确认 | 不需要 HertzFlow；暂时不接 Freqtrade |
| 本方案默认 | Alpha 为首版产品数据源；普通 Binance 行情只作为底本能力和对照数据 |
| 本方案默认 | 单用户本地研究应用，TypeScript、单仓库、SQLite，先完成结构与证据闭环 |
| 待实施验证 | 上游依赖可运行性、Alpha 数据覆盖和频率、策略参数、性能容量 |

“不限链”在首版中的含义是：按 Alpha 提供的资产列表处理不同链的代币身份。它不意味着首版要接入每条链的 RPC、钱包追踪或独立 DEX 数据源。

## 首版用户流程

1. 查看 Alpha 资产集合与采集范围，知道哪些资产尚未覆盖及原因。
2. 查看首轮上涨、回撤观察、筑底、突破等状态中的候选。
3. 打开候选图表，查看触发时间、关键价格、规则输入和数据质量。
4. 人工记录形态标签和备注；原始机器判断保持不变。
5. 回放同一数据，核对判断是否可复现；查看触发后各时间窗口的表现。
6. 查看采集失败、积压、缺失 K 线、规则版本和最近一次成功运行时间。

## 与旧项目的关系

旧项目用于提供经验和回归场景，不作为新项目运行依赖。新项目使用自己的配置、数据库、目录和入口。旧项目的五维评分政策不自动继承；首版展示结构状态与证据，不制造一个看似精确的综合“胜率分”。

旧项目 `package.json` 声明 `AGPL-3.0-only`。本包没有复制其应用源码。后续如需移植，应先记录具体文件的来源、权利和许可处理；不得仅因目录相邻就默认可以换成 MIT。第三方无需访问旧项目私有记录便可完成本方案。

本包不陈述旧服务的当前部署状态，也不授权改变旧服务。旧项目在其他会话中的实施或部署进展不等于新项目已完成。

## 成功标准

工程成功：输入可追踪、状态可解释、断点可恢复、实时与回放一致、第三方能够重现报告。

研究成功：对事先固定的资产集合和时间区间，如实呈现触发与失败样本，能判断某条规则是否改善筛选。没有信号、信号过少或结果无优势，也可以是有效的研究结果。

工程验收不以盈利为条件；工程通过也不代表策略已经具有交易优势。
