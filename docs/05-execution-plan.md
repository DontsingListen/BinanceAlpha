# 分阶段执行计划

## 总体安排

默认由一名熟悉 TypeScript、行情数据和 SQL 的工程师实施，另由一名审核者复核关键时间语义和验收报告。一个人可以兼任，但复核结论应注明未进行独立审查。

建议拆成可独立审核的提交或 PR，不把采集、策略、UI 和参数优化混在一次改动中。每个工作包应有变更说明、测试证据、已知限制和回退方法。

## M0 底本与数据可用性

| 工作包 | 具体动作 | 必交产物 | 验收 |
| --- | --- | --- | --- |
| M0.1 | 在隔离目录取得固定上游提交，核对许可证、manifest、脚本和依赖；运行其 build/test | `reports/m0-upstream.md`，命令、版本、退出码、失败分类 | 不把测试文件存在写成测试已通过；失败能归因到环境或源码 |
| M0.2 | 取代币列表、交易对列表；选至少 5 个可验证交易对，采集当前与历史 5m 页 | 脱敏原始 JSON、请求参数、响应哈希、身份映射表 | alphaId/baseAsset/quoteAsset 对应正确；没有按 ticker 模糊匹配 |
| M0.3 | 用两个以上时间页检查排序、重叠、空页、实际条数、收盘边界、最早覆盖；采集运行环境可访问性 | `reports/m0-alpha-data.md` 和 fixtures | 明确能否获得 300 根连续历史、7 天目标覆盖；列出未知而非默认成功 |
| M0.4 | 最小复现 R01/R02，检查 R03 时间含义；列出要移植的模块 | `reports/m0-adoption.md` 和复现输入/结果 | 通过追加未来行情对比，确认哪些上游特征不能用于原时点判断 |

建议取得上游的命令如下；本次交付没有执行这些安装或测试命令：

```bash
git clone --no-checkout https://github.com/aleks-ent/pump-dump-crypto-screener.git .upstream/pump-dump-crypto-screener
git -C .upstream/pump-dump-crypto-screener checkout --detach ec14f855b2fdd65b2c9b039d1b7661d4da6ef26b
```

先审查 package scripts 与安装脚本，再在固定 Node/pnpm 环境安装和执行。不要启动其 Telegram/PM2 入口，也不要为了跑测试填入真实交易账户。`.upstream` 不应成为新项目的运行依赖或提交进仓库的大型源码副本。

M0 出口：数据路径可行，移植清单可追踪，环境版本明确。若历史不足但实时可取，允许从前向采集开始积累，保持 WARMUP；必须调整排期，不能用假数据宣称 Alpha 已可验证。

## M3 连续运行

| 工作包 | 具体动作 | 产物 | 验收 |
| --- | --- | --- | --- |
| M3.1 | 单 writer、租约、增量优先、有界回填、共享限速与取消 | worker 与调度器 | 双启动被阻止；增量不会被回填饿死；T11/T12 |
| M3.2 | 原子写入 journal、决策和检查点；处理迟到/修订 | 在线运行入口 | 崩溃重启无重复事件；原决策不被修订覆盖；T05/T09/T10 |
| M3.3 | 健康状态、队列、请求量、延迟、覆盖、磁盘与异常统计 | 状态 API、结构化日志 | 能区分无行情、无信号、采集失败和处理失败 |

运行日志不是唯一研究证据；研究结论必须能定位到 SQLite 中的 run、输入版本和事件。正常运行不打印原始响应全文或任何敏感配置。

M3 出口：5 对连续运行至少 24 小时，完成一次重启和一次断网恢复；在线事件可由 journal 重现。

## M5 首版验收与交接

默认试运行 50 对，连续观察至少 7 个完整 UTC 日。资产不足 50 对时使用实际数量并说明；不足 20 个独立 setup 时继续标记样本不足，不为凑样本放宽规则。7 天只是工程观察窗口，不是统计充分性证明。

| 指标 | 建议验收值 | 口径 |
| --- | --- | --- |
| 在线增量成功率 | ≥99% | 符合资格的计划任务；所有非成功原因保留。人工维护时段单独列出 |
| 闭合到入库延迟 | p95 ≤120 秒 | 已进入增量模式的采集范围；排除回填并同时报告回填耗时 |
| 决策一致性 | 固定 journal 回放 100% 一致 | 比较稳定事件字段/哈希；排除独立记录的回放作业执行时间 |
| 幂等性 | 重启/重试新增重复事件为 0 | 在固定故障注入样本上核对事件唯一键 |
| 证据可追踪 | 所有决策均可定位输入、版本和原因 | 任一缺失均不通过 |
| 故障恢复 | 断网、429、异常退出、数据库恢复演练通过 | 不要求外部故障期间产生新信号 |

这些是计划门槛，M0 若发现外部条件不支持，应在试运行前修改并记录依据，不能在结果出来后降低门槛而不披露。

交付代码、运行说明、数据字典、测试与运行报告、迁移/恢复步骤、已知问题列表、第三方来源清单和固定研究示例。最后按 [验证指南](06-verification-and-handoff.md) 逐项复核。

## 扩展顺序

首版通过后，优先做 VCP 对照实验、扩大 Alpha 采集范围和其他报价币种。每项扩展先固定假设，再做样本外对照。OI/资金费率、多交易所和独立 DEX 数据应分别立项，不能因为底本有相似目录就自动进入当前范围。

## 暂停点与回退

数据失败只暂停受影响来源/资产，保留全部历史证据；运行错误停止新事件生成并保留检查点。应用升级可回退代码与配置；数据库先备份，schema 不兼容时使用恢复副本核对，不能擦除新采集数据。文档和规则变化更新 ADR、policy 版本与已知问题，不维持两套含义不同却同名的规则。
