# 验证与接手指南

## 第三方接手步骤

1. 阅读 README 的状态表，确认收到的是方案包，应用代码尚未开始。
2. 运行 `python3 tools/verify_handoff.py`，核对本地文件哈希和链接。阅读 evidence 中的固定提交与来源记录。
3. 阅读范围、架构和规则规格；将不理解的语义记录为具体问题，避免自行套用其他仓库的默认含义。
4. 从 M0 开始收集运行证据。首先验证 Alpha 身份映射、历史覆盖和上游可用性，随后按阶段实施。
5. 每个阶段留下变更提交、测试命令、输入数据哈希和结果。审核完成才更新进度；本包没有为未来阶段预先填写“通过”。

第三方可以在任意目录接手，本包内部使用相对链接。旧项目地址只用于说明背景；不要求其存在。当前不需要账户、密钥、服务器访问或用户钱包。

| --- | --- | --- | --- |

## 最小人工复核集

至少准备以下合成场景，并人工写出期望转移序列：正常首轮至确认；直接 V 形反弹无筑底；回撤超过上限；筑底量未缩；低量越过门槛后持续高位；回落再有效突破；突破过度延伸；突破后失效；第 6 根才满足确认；72 小时整点到期；末根未闭合；缺口后补齐；零量基准；同名不同资产；已消费行情被修订。

合成场景用于证明实现符合定义，不能用于证明市场有效性。真实样本先按截至触发时刻的图进行形态标注，再单独查看未来表现；标签记录 `seenThroughAt`，避免把事后赢家外观写成事前可知判断。

## 研究评估方法

- 数据集冻结：保存资产集合版本、采集范围、时间区间、原始数据哈希、规则配置、代码版本与运行模式。
- 分层：至少按时间、成交活跃度和资产分别报告。统计基本单位为 setup，重复采样和多个结果窗口不当作独立信号数。
- 对照：与“只识别首轮上涨”的固定规则及预先定义的时间对照比较；使用相同资产集合、覆盖要求、时间范围和结果口径。历史模拟不与真实在线结果混算。
- 样本外：开发与验证按时间分开，留至少 96 小时间隔；同一 setup 不跨集合。不得看完验证结果继续调参却仍称它是样本外。
- 报告：除命中/失效比例，还展示样本数、缺失数、MFE/MAE 分布、中位数、极值和各资产贡献。小样本明确保留不确定性，不用漂亮均值替代分布。
- 模拟收益：只有另行固定成交和成本模型时才提供，并与形态统计分开。测试过的参数组合数量也应披露。

## 实施阶段证据包

每次阶段交付建议包含 `reports/<stage>/`，内容为：

| 文件 | 内容 |
| --- | --- |
| `manifest.json` | 代码提交、运行环境、依赖锁哈希、schema/policy 版本、输入/输出哈希、开始与结束时间 |
| `commands.txt` | 实际执行的命令和退出码，移除凭据与个人敏感信息 |
| `results.md` | 需求到测试的对应、通过/失败/未执行，以及实际限制 |
| `fixtures/` | 可分享的固定输入，标明真实脱敏或人工合成 |
| `diff.json` | 回放一致性或规则版本对比结果，保留失败样本 |
| `known-issues.md` | 严重性、影响、复现条件、负责人角色、处理阶段 |

不得只交一张通过截图或总测试数。审核者应能选择任意事件，通过实际命令重现结果；日志不能仅保留最后一次成功运行。

## 开始实施前需处理的决定

这些事项已有默认建议，通常可由实施者在 M0 按证据确定并记录，无须为每个常规技术选择重新等待用户确认。

| 事项 | 默认建议 | 何时需要调整 |
| --- | --- | --- |
| 首版市场 | Alpha USDT；50 对试运行 | 真实可用交易对不足或容量证据要求改变 |
| 历史范围 | 近 7 天回填，至少 300 根连续 5m | 上市不足/接口历史不足；保留 WARMUP 并积累 |
| 运行环境 | 本地单用户；支持中的 Node LTS | 正式服务器运行是另一步部署工作 |
| 规则参数 | 使用 proposed v0 并冻结一个研究 run | 仅在开发集调参；变更需要新版本 |
| 应用许可证 | M0 按实际移植清单确定 | 复制旧 AGPL 源码或新引入不同许可时重评 |
| 图表/SQLite 依赖 | 复用可独立测试的上游能力或成熟小依赖 | 兼容性、授权或维护成本不合适 |

## 风险与审核重点

| 风险 | 早期检测 | 应对 |
| --- | --- | --- |
| 当前资产列表造成幸存者偏差 | 报告是否有历史集合版本 | 从现在持续存集合快照，回溯结果标明受限 |
| K 线修订或延迟造成前视 | R01/R02 复现，T07–T09 | 不可变输入版本、真实 observedAt、分开回放模式 |
| 公共接口不稳定或字段变化 | M0 fixtures 与持续契约监测 | 适配器隔离、暂停、覆盖状态；不伪造回填成功 |
| 参数过拟合 | 参数试验次数与时间划分 | 冻结规则、留独立验证区间、分资产报告 |
| 单币极端行情主导平均收益 | 各资产贡献与分布 | 单独展示极值，按 setup/资产分组 |
| 底本解耦成本高 | M0 移植清单和测试结果 | 缩小移植范围，不把无关服务带入运行时 |
| 采集范围小却宣称全市场 | 元数据总数、采集数、有效数同时展示 | 保留未覆盖资产，扩容单独验收 |
